# 云朵小镇 · 推推奇遇

> 治愈系萌宠小镇 × 限步推箱子 × 每日同题竞技的微信小游戏立项资料（v4.0）

## 这是什么

本仓库是一套**完整的小游戏立项前置资料**，不是可运行的成品代码。包含产品定义、流程图、技术方案、执行排期与高保真交互稿五部分。

核心方法论（v4.0 · 个人开发者版）：**前两条是死活线，过不了就没有后面**——

1. **内容成本**：内容能不能程序生成，而不是手工设计？
2. **分享必然性**：不分享，游戏体验是否残缺？
3. **失败二值化**：输赢是不是"过 / 不过"？
4. **美术依赖度**：能不能不用美术资源就成立？
5. **广告即需求**：玩家会不会自己"想看"广告？

## 核心结论（速读 · v4.0）

### 1. 技术可行，商业预期要大幅下调

- 个人主体只能做纯 IAA：DAU 1000 ≈ 60-80 元/日（eCPM 25 元保守口径，见产品文档 7.4）
- **真正的生死线是获量，不是开发**

### 2. 两条死活线（个人开发者唯一无法用勤奋弥补的事）

- **内容成本**：关卡必须程序生成 + 校验器过滤，不能手调
- **分享必然性**：不分享，游戏体验必须残缺——分享是机制的一部分，不是可选动作

### 3. v4.0 的两个核心设计（针对死活线）

- **限步通关 + 步数锁死**：每关有步数预算，耗尽即失败；撤销回退棋盘但不返还步数。把"47 步 vs 43 步"变成"过 / 不过"，痛感真实
- **小镇每日赛**：全服每天同一关、每人一次机会（看广告可加一次）；结果海报"用了 5 步 · 击败 87% 的镇民"自带传播。每天只产 1 关，内容成本趋近于零

### 4. 3×2 周 MVP 节奏（取代 13 周直线排期）

| 段 | 周期 | 目标 | Go/No-Go |
|:---|:---|:---|:---|
| 第 1 段 | W1-2 | 限步引擎 + 10 关 + 本地对比 | 有没有人自发分享成绩 |
| 第 2 段 | W3-4 | 每日赛 + 海报 + 体验版 | 分享率与留存基线 |
| 第 3 段 | W5-6 | 按数据决策 | 加内容 / 换题材 / 止损 |

## 三层社交结构（v4.0 修订）

```
第一层 · 魔鬼关卡（限步强化）  ← 情绪地基：制造真实的"就差一步"
      ↓
第二层 · 求助机制              ← 承接情绪：把"痛"转成"关系互动"
      ↓
第三层 · 小镇每日赛            ← 放大传播：全服同题 + 结果海报
                                （1v1 挑战链接接龙 → v1.1 扩展）
```

**顺序不能反** —— 没有第一层制造痛点，上面两层都是空的。参考《羊了个羊》：裂变不是设计出来的，是难度逼出来的。
