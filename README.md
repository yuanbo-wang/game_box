> 治愈系萌宠小镇 × 推箱子解谜 × 三层社交结构的微信小游戏立项资料

## 这是什么

本仓库是一套**完整的小游戏立项前置资料**，不是可运行的成品代码。包含产品定义、流程图、技术方案、执行排期与高保真交互稿五部分。

核心方法论：**任何设计都必须通过"上手门槛 / 技巧天花板 / 单局时长 / 社交钩子 / 变现卡点"五项筛选器**，不满足 4 项的砍掉。

## 交互稿

直接用浏览器打开 `prototype/index.html`，或用静态服务器托管：

```bash
npx serve prototype
```

## 三份文档的核心结论（速读）

### 1. 这个项目可行，但有三处必须修正

| 项 | 原始说法 | 修正 |
|:---|:---|:---|
| 变现预期 | DAU 1000 → 150-300 元/日 | eCPM 按 25 元保守算 → **60-80 元/日** |
| 软著排期 | 第 7-8 周提交 | **第 2 周必须提交**（1-3 个月出证，是审核前置） |
| 开发周期 | 8 周 | **12-14 周** |

### 2. 推箱子的"社交原罪"

推箱子在"单局时长"和"社交钩子"上有**结构性缺陷**，靠加机关补不了，必须靠社交层重做。

**核心命题**：把"内敛的成就感"（我解出来了）改造成"外显的、可比的痛点"（我比你少 4 步）。

### 3. 三层社交结构（本项目最大的设计产出）

```
第一层 · 魔鬼关卡  ← 情绪地基：制造"就差一点"的痛
      ↓
第二层 · 求助机制  ← 承接情绪：把"痛"转成"关系互动"
      ↓
第三层 · 异步 PK   ← 放大传播：把"互动"转成"传播链"
```

**顺序不能反** —— 没有第一层制造痛点，上面两层都是空的。参考《羊了个羊》：裂变不是设计出来的，是难度逼出来的。

## 三处"反直觉"的设计决策

| 决策 | 常规做法 | 本方案 | 理由 |
|:---|:---|:---|:---|
| PK 模式 | 镜像版（随机机关） | **同关卡同配置** | 随机破坏公平性，PK 失去意义 |
| 记分口径 | 实际总步数 | **历史最少步数** | 否则谨慎玩家永远输给莽撞玩家 |
| 机关数量 | 首发 5 个 | **首发 3 个** | "音乐花丛"静音不可玩；"镜子小屋"设计成本过高 |
