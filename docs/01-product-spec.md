# 《云朵小镇·推推奇遇》产品文档 v3.0

> 文档版本：v3.0（社交化改造版）
> 编写日期：2026 年 10 月
> 相对 v2.0 的核心变更：修正变现预期、重排资质排期、确立"三层社交结构"、废弃"镜像版 PK"改为"同版复刻比步数"、机关从 5 个收敛为 3 个首发

---

## 一、产品概述

### 1.1 一句话定位

**《云朵小镇·推推奇遇》是一款"治愈系萌宠小镇 + 推箱子解谜 + 轻社交对抗"的微信小游戏，核心卖点是"3 秒上手的可爱推箱子，和好友比谁用的步数最少"。**

### 1.2 设计信条（v3.0 新增）

这份文档的每一条设计，都必须通过下面这把筛选器的检验。**任何不满足 4 项以上的设计，都要被砍掉或返工。**

| 筛选维度 | 判断问句 | 本产品的应对 |
|:---|:---|:---|
| **A. 上手门槛** | 3 秒内能玩懂吗？ | 滑动即可移动，规则即"把物件推到星光台" |
| **B. 技巧天花板** | 玩 100 次和玩 10 次能拉开差距吗？ | 比"最少步数"，最优解需要预判与逆向思维 |
| **C. 单局时长** | 30 秒 - 3 分钟，可随时中断？ | 前 20 关锁定 2-3 分钟内可解；单局可暂停 |
| **D. 社交钩子** | 有没有不需要玩家主动想起就会产生的炫耀/求助点？ | **三层社交结构**（见第六节） |
| **E. 变现卡点** | 失败/瓶颈是否高频且高痛感？ | 魔鬼关卡 + 提示 + 复活，均天然接激励视频 |

### 1.3 v2.0 遗留问题的修正（必读）

| 问题 | v2.0 的说法 | v3.0 的修正 |
|:---|:---|:---|
| 品类天然短板 | 未提及 | 明确认定：**推箱子在"单局时长(C)"和"社交钩子(D)"上有结构性缺陷**，靠加机关补不了，必须靠社交层重做 |
| 收入预期 | DAU 1000 → 150-300 元/日 | 按 eCPM 25 元、人均日看 2.5 次激励视频重算：**DAU 1000 → 约 60-80 元/日** |
| eCPM | ">50 元" | 那是微信官方"上限参考值"；**实际区间 15-40 元**，按 25 元做保守测算 |
| 软著排期 | 第 7-8 周提交 | **第 2 周必须提交**（软著是审核前置条件，1-3 个月出证，不能后补） |
| 开发周期 | 8 周 | **12-14 周**（个人开发，含资质等待期） |
| 机关数量 | 首发 5 个 | **首发 3 个**（传送带 / 滑梯弹簧 / 小伙伴），另 2 个延后 |
| PK 设计 | "同一关卡的镜像版本" | **废弃**。改为"同关卡同配置，比最少步数"（镜像版破坏公平性，见 6.4） |
| 收入模型 | 组件使用率 90% | 按更真实的 60-70% 测算 |

> **重要提示**：本文档的 TAM/SAM 数据来自公开渠道，仅用于方向判断，不作为财务承诺。

## 二、产品定位与目标用户

### 2.1 定位

| 维度 | 内容 |
|:---|:---|
| **品类** | 路径规划解谜（推箱子子类） |
| **平台** | 微信小游戏（个人主体） |
| **变现** | 纯 IAA（激励视频广告） |
| **美术** | 柔和手绘 + Q 版卡通 + 温暖治愈 |
| **差异化** | 萌宠小镇叙事 + 可爱物件 + **好友最少步数比拼** |

### 2.2 目标用户

| 画像 | 特征 | 对应设计 |
|:---|:---|:---|
| **核心用户**（18-35 岁女性偏多） | 喜欢治愈萌系，碎片时间（通勤/午休/睡前） | 可爱画风、单局 2 分钟、无惩罚 |
| **泛用户** | 被画风吸引的轻度玩家，要"不烧脑但有成就感" | 前 20 关零挫败、无限撤销 |
| **传播用户** | 爱在好友榜比拼、爱晒截图 | 最少步数榜、"就差一步"提示、挑战链接 |

### 2.3 竞品与差异化

| 竞品 | 平台 | 核心玩法 | 与本产品的关系 |
|:---|:---|:---|:---|
| 《箭了又箭》 | 微信小游戏 | 拔箭头路径规划 | 同赛道，无角色叙事；**变现策略可借鉴** |
| 《羊了个羊》 | 微信小游戏 | 消除 + 社交裂变 | 品类不同，但**"魔鬼关卡驱动裂变"的逻辑是本产品的核心参考** |
| 《动物餐厅》 | 微信小游戏 | 模拟经营 | 非解谜，治愈画风可借鉴 |
| 《旅行青蛙》 | 移动端 | 放置养成 | 非解谜，"无压力陪伴"情感可借鉴 |

**差异化定位声明**：本产品**不以"题材空白"为卖点**（治愈萌宠解谜已有多个同类），差异化建立在 **① 美术质量 ② 好友步数对抗的竞技深度** 这两点上。

## 三、核心玩法设计

### 3.1 基础玩法

经典推箱子：玩家在网格地图移动，推动"小物件"前进（只能推、不能拉），撞墙或无路可推时停下。**将所有物件推到"星光台"上即通关。**

操作（移动端）：

- **滑动屏幕** → 角色朝对应方向移动一格
- **长按角色** → 高亮当前可推动物件范围
- **双指缩放** → 全局视野 / 局部视野切换
- **撤销按钮** → 无限撤销，无成本

### 3.2 首发机制（3 个，砍掉 2 个）

#### 机制一：彩虹传送带 ✅ 首发

场景中有彩色传送带，物件被推到传送带上则自动运送到相邻区域。

- **教学关卡**：第 1-5 关，单条直线传送带
- **设计要点**：传送带让玩家需要"预判两步之后的局面"，是**性价比最高的机制**
- **风险**：低

#### 机制二：滑梯与弹簧 ✅ 首发

滑梯上的物件被推动后自动滑行至障碍或平地；弹簧格把物件弹射到远处。

- **教学关卡**：第 6-10 关，单向滑梯
- **设计要点**：把"精确落点"变成"范围落点"，降低操作精度要求，提升趣味
- **风险**：低

#### 机制三：小伙伴合作 ✅ 首发

可切换控制主角与小伙伴（小兔子、小松鼠），小伙伴可达狭窄通道，需配合解谜。

- **教学关卡**：第 11-15 关，主角推物件开门，小伙伴穿门到另一侧推物件
- **设计要点**：切换控制 = 一个关卡等于两个棋盘，**深度高但实现中等**
- **风险**：中（需做"双角色状态机"，但和核心引擎同构）

#### 机制四：音乐花丛 ⏸️ 延后至 v1.1

靠音效变化判断隐藏目标位置。

- **砍掉原因**：**在静音环境（地铁/办公室）下直接不可玩**，与"碎片化场景"核心定位冲突
- **补救方案**：若要做，必须提供视觉替代（颜色/光晕变化），不能只靠声音

#### 机制五：镜子小屋 ⏸️ 延后至 v1.1

镜像区域联动移动。

- **砍掉原因**：状态空间翻倍，**关卡设计成本与难度控制成本极高**；且玩家理解成本高，与"零门槛"冲突
- **补救方案**：可做成独立的"镜屋模式"，不混入主线

### 3.3 关卡结构（首发 30 关）

| 章节 | 主题 | 关卡 | 核心机制 |
|:---|:---|:---|:---|
| 第一章·搬新家 | 小镇入口 | 1-10 | 基础推箱子 + 彩虹传送带 |
| 第二章·滑梯乐园 | 游乐区 | 11-20 | 传送带 + 滑梯弹簧 |
| 第三章·朋友派对 | 小镇广场 | 21-30 | 传送带 + 滑梯 + 小伙伴全面融合 |

**难度曲线（每章内部）**：

- 第 1-3 关：教学关（引入新机制，几乎必过）
- 第 4-7 关：组合应用（需要几步思考）
- 第 8 关：**魔鬼关卡**（见 6.1，专门制造卡点）
- 第 9-10 关：综合挑战

**为什么首发只做 30 关**：50 关会让首发周期拉长到 14 周以上；30 关可在第 10 周前完成并留出测试时间，后续每 2 周追加 10 关。

### 3.4 反馈系统

| 反馈类型 | 触发条件 | 表现 |
|:---|:---|:---|
| 操作反馈 | 每次移动 | 脚下星星粒子 + "啾"音效 |
| 推动反馈 | 物件被推动 | 物件弹跳动画 + 地面脚印 |
| 传送带激活 | 物件上传送带 | 彩虹光效 + 欢快音效 |
| 正确放置 | 物件到目标点 | 物件发光 + 风铃声 + 星光台亮起 |
| 全部完成 | 所有物件归位 | 全屏星星粒子 + 通关音乐 |
| 卡关 | 物件被推到死角 | 物件抖动 + 角色歪头 + 提示可撤销 |
| **"就差一步"** | 步数比好友多 1-2 步 | 结算页高亮提示（**社交核心反馈**） |

### 3.5 辅助功能

- **步数记录**：当前步数 + 历史最优步数（**最优步数是社交对比的唯一口径**）
- **撤销 / 重置**：无限次，无成本
- **提示系统**：每关 3 次免费提示，超出观看激励视频
- **角色换装**：通关得星星解锁装扮（纯装饰）
- **半开放探索**：部分关卡信息藏在场景装饰中

## 四、美术风格设计

### 4.1 视觉定位

**柔和手绘 + Q 版卡通 + 温暖治愈**

| 规范 | 内容 |
|:---|:---|
| **色彩** | 奶油白、淡粉、薄荷绿、鹅黄为主；辅以天蓝、珊瑚橙；低对比度 |
| **线条** | 圆润粗线条，边缘有轻微手绘抖动感（蜡笔/水彩笔触） |
| **背景** | 多层视差：远景云朵彩虹 / 中景小镇建筑 / 近景关卡场景 |
| **光影** | 柔和全局光，物件有淡投影 |

### 4.2 角色与物件

| 元素 | 描述 |
|:---|:---|
| 主角·小狐狸 | 圆滚滚橙色小狐狸，大尾巴，豆豆眼，行走有弹跳感 |
| 主角·小猫（可选） | 奶油色小猫，粉色肉垫，蝴蝶结 |
| 小物件 | 小南瓜、毛线球、礼物盒、小蛋糕（按章节变化） |
| 星光台 | 圆形木质台面，边缘星星装饰，放置后亮起柔光 |
| 彩虹传送带 | 彩色条纹，转动时流光 |
| 滑梯与弹簧 | 木质滑梯；弹簧格为蘑菇造型 |
| 小伙伴 | 小兔子、小松鼠，圆润可爱，专属动作 |
| 场景装饰 | 云朵、彩虹、小花、蘑菇、木牌、路灯 |

### 4.3 美术生产流程（AI 辅助）

**AI 生成**（治愈系 Q 版 LoRA）：

- 章节主题背景、场景装饰、封面图、宣传素材

**代码绘制**（Phaser Graphics / 程序化贴图）：

- 角色精灵、物件、传送带、目标点、网格线、UI 边框、粒子

**风格统一策略**：AI 背景图先做柔化处理（降对比度 + 统一色调），再与代码绘制元素合成。

> **⚠️ 前置验证项**：AI 生成风格的**一致性**是本项目最大的隐性工作量。**第 1 周必须先做 3-5 张样张验证**，通过后再批量生产。

## 五、技术方案（摘要）

> 详细内容见 `docs/03-dev-spec.md`

| 维度 | 选择 | 理由 |
|:---|:---|:---|
| 引擎 | Phaser 3 | 2D 解谜首选，社区成熟，支持微信小游戏适配层 |
| 语言 | TypeScript | 类型安全，适合复杂解谜逻辑 |
| 状态管理 | 纯函数棋盘引擎 | 逻辑与渲染解耦，便于单测与撤销/回放 |
| 部署 | 微信小游戏 | 目标平台 |
| 后端 | 轻量云函数 / Serverless | 仅用于挑战赛数据与排行榜（推荐微信云开发） |

**核心架构**：棋盘引擎为纯函数模块，每次操作返回**新的不可变状态** + **事件列表**，渲染层根据事件播放动画。

**包体预算**：代码包 ≤ 2MB + 资源包 ≤ 2MB（总计 ≤ 4MB，首包建议压到 3.5MB 以内留余量）。

## 六、社交化改造方案（v3.0 核心）

### 6.1 问题定义：推箱子的"社交原罪"

| 维度 | 推箱子的天然状态 | 阻碍 |
|:---|:---|:---|
| 社交钩子 | 成就感是"内敛"的（我解出来了） | 不如消除类有直观可比性 |
| 单局时长 | 后期关卡 5-10 分钟正常 | 破坏了异步 PK 的"同一起跑线"前提 |

**核心命题**：把"内敛的成就感"改造成"外显的、可比的身份标签 / 痛点"。

**隐藏的致命问题**：推箱子的成绩**没有天然可比性**。消除类比"过了没有"（二值、直观、人人焦虑）；推箱子是"47 步 vs 43 步"，两者都过了，**玩家感受不到差距的痛感**。

### 6.2 三层社交结构

```
┌─────────────────────────────────────────────┐
│  第三层：异步 PK（关系链对抗）                │  ← 获客层
│  小镇挑战赛——同关卡同配置，比最少步数        │
├─────────────────────────────────────────────┤
│  第二层：求助机制（弱关系互动）               │  ← 留存层
│  卡关 → 求好友 → 好友点一下"加油"           │
├─────────────────────────────────────────────┤
│  第一层：魔鬼关卡（制造痛点）                 │  ← 情绪层（地基）
│  每章第 8 关设计成"看似能过"的卡点           │
└─────────────────────────────────────────────┘
```

**因果关系**：魔鬼关卡制造"痛" → 求助把"痛"转成"关系互动" → 异步 PK 把"互动"转成"传播链"。

**没有第一层，上面两层都是空的。** 参考《羊了个羊》：它的裂变不是设计出来的，是第二关的难度逼出来的。

### 6.3 第一层：魔鬼关卡

**设计原则**：《羊了个羊》的第二关不是"随机难"，是精心设计的"**看似能过**"。

| 要素 | 做法 | 为什么 |
|:---|:---|:---|
| 视觉上可解 | 棋盘是标准规格，不吓人 | 玩家愿意开始 |
| 有明确接近感 | 前 70% 顺利，最后 1-2 个物件卡死 | 制造"就差一点"的痛感 |
| 有微小侥幸 | 有 1-2 种操作顺序能过，但试不出来 | 让玩家相信"再试一次就行" |
| 失败不羞辱 | 提示"再想想，你一定可以" | 不破坏治愈系人设 |

**关卡结构**（6×6，2 物件示例）：

```
初始状态：
  - 物件 A 与目标点几乎在一条直线，看起来推 3 步就到
  - 物件 B 需绕路，路径上有个"看起来能过"的窄缝

真实解法：
  - 必须先推 B 到特定位置堵住退路，再用 A 完成"空间交换"

痛点设计：
  - 90% 的人先推 A（最直觉）→ B 永远推不出来（死局）
  - 游戏不说"你错了"，只显示"再试试"（无限撤销）
```

**关键**：让玩家在**第 3-5 次尝试后**才意识到"我一开始的思路就是错的"。这个"意识到"的瞬间，就是分享欲望最强的时刻。

**配套造势**：

- 关卡名：《就差一步》
- 通关文案："你用了 X 步，比 92% 的镇民都聪明 🎉"
- 分享海报印："**据说 90% 的人在这里放弃**"

### 6.4 第二层：求助机制

推箱子的求助**不能照抄**《羊了个羊》的"分享给好友帮你玩"——推箱子没法"帮玩"（给好友他也得自己解）。三种形态：

| 形态 | 机制 | 好友收到 | 侵入性 |
|:---|:---|:---|:---|
| **① 加油** | 卡关时点"呼叫小伙伴" | 可爱卡片，点一下给"加油"，玩家得 1 次提示 | 最轻（高频、无压力） |
| **② 传地址** | 把这一关送给好友挑战 | 好友进入**同一关**，双方独立解 | 中 |
| **③ 组队解谜** | 邀请好友一起解 | 好友能看到玩家已走的前 N 步，从中间继续 | 重（实现复杂） |

**首发只做 ① 和 ②。** ③ 需序列化状态传输，ROI 不高，延后。

**反骚扰硬约束**：

1. 每人每日求助上限 **3 次**（对齐微信分享频次隐性限制）
2. 同一好友 **24 小时内只能被求助 1 次**
3. **求助必须"给好友东西"**：好友点一下能拿到星星/提示，这样他才不烦
4. **不做"分享才能复活"**（微信不鼓励，伤体验）

**文案设计**（情绪化，别机械）：

| 场景 | 文案 |
|:---|:---|
| 玩家发出求助 | "我在《就差一步》卡住了，小松鼠说它也没办法 🥺" |
| 好友看到 | "你的朋友在《就差一步》需要帮助！点一下为他加油 ✨" |
| 好友帮完后 | "你帮 TA 加油了！获得 1 颗小星星 ⭐" |

### 6.5 第三层：异步 PK（小镇挑战赛）

**⚠️ 废弃 v2.0 的"镜像版"设计。** 理由：

- **不可比**：机关配置变了，步数就没有可比性 → PK 失去意义
- **不公平**：随机配置导致一方明显更难 → 玩家觉得不公平

**正确做法：同关卡、同配置、比最少步数 + 用时。**

```
流程：
1. 玩家 A 通关第 N 关 → 弹出"发起挑战"
2. 生成挑战链接 → 分享给好友 B
3. B 点开 → 进入【第 N 关 复刻版】
   - 棋盘、物件、机关 完全一致（保证公平）
   - B 不知道 A 用了多少步（避免"反正赢不了"的放弃）
4. B 通关后 → 揭晓成绩
   - A: 23 步 / B: 19 步 → "你赢了！比 A 少用 4 步 🏆"
   - B 输了 → "就差 2 步！再来一次？"（触发反向挑战）
5. 双方可继续接龙挑战，形成传播链
```

| 设计点 | 作用 |
|:---|:---|
| 隐藏对方成绩 | 避免碾压式差距导致弃玩 |
| "差一点"高亮（差 ≤2 步） | 直接触发再挑战 |
| 失败可反向挑战 | 输的人有翻盘机会 → 传播链不断 |
| 接龙机制 | 一个链接传多手 → 指数级传播 |

**记分口径（关键细节）**：只算**这一关的历史最少步数**（允许反复重试取最优），不算总步数。

- 错误做法：算实际走了多少步 → 谨慎玩家永远输给莽撞玩家
- 正确做法：算历史最少步数 → 比的是"能不能找到更优解"，才有技巧深度

**排行榜**：

- 好友最少步数榜（刺激"我要比他少 1 步"）
- 章节进度榜（制造"他比我快"的焦虑）
- **不做总榜**（对普通玩家无意义）

### 6.6 分享激励设计

| 场景 | 激励 |
|:---|:---|
| 通关后分享成绩 | 1 次免费提示 |
| 邀请好友首次进入 | 双方各得 1 次"机关预览" |
| 排行榜超越好友 | 弹出"炫耀"按钮，生成可爱海报 |
| 卡关超 5 分钟 | 提示"求助好友" |

**注意**：分享**不可硬来**，必须在玩家有"炫耀"或"求助"动机时自然触发。单用户每日主动分享 ≤ 3 次。

### 6.7 落地优先级

| 优先级 | 功能 | 为什么先做 | 工作量 |
|:---|:---|:---|:---|
| **P0** | 魔鬼关卡 + "差一点"文案 | 社交地基，没它后面都空 | 2-3 天 |
| **P0** | 求助-加油（形态①） | 最简单的社交闭环 | 1-2 天 |
| **P1** | 异步 PK（同关卡比最少步数） | 核心获客引擎，需后端 | 3-5 天 |
| **P1** | 好友最少步数榜 | 开放数据域，成本低 | 2 天 |
| **P2** | 分享海报生成 | 传播载体 | 2 天 |
| **P2** | 组队解谜（形态③） | ROI 低，可砍 | — |

**顺序不能反**：先魔鬼关卡（制造情绪）→ 再求助（承接情绪）→ 最后 PK（放大情绪）。

### 6.8 三个必须警惕的坑

1. **把社交做成"任务"**："分享得 3 个提示"是任务式分享，玩家会烦。有效的分享是情绪驱动的。
2. **魔鬼关卡做成"真无解"或"纯随机"**：必须保证**有解且解是确定的**。如果玩家发现靠运气，会愤怒而非分享（《羊了个羊》的口碑雷区）。
3. **忘记微信分享限制**：单用户每日主动分享 ≤3 次；不能"必须分享才能继续"；分享卡片必须走官方接口。

## 七、商业化设计

### 7.1 变现模式：纯 IAA（激励视频）

**硬约束**：个人开发者在微信小游戏平台**无法开通内购支付**，只能广告变现。若后期想开内购，需升级企业主体（需公司资质、对公账户）。

### 7.2 广告触发点

| 触发场景 | 类型 | 频次限制 |
|:---|:---|:---|
| 关卡失败后复活 | 激励视频 | 每关最多 1 次 |
| 获取提示 | 激励视频 | 每关最多 2 次（前 3 次免费） |
| 解锁隐藏关卡 | 激励视频 | 每章 1 次 |
| 领取每日奖励 | 激励视频 | 每日 1 次 |
| 结算界面"翻倍" | 激励视频 | 每日 3 次 |

**不设 Banner 和插屏广告**（破坏解谜沉浸感）。

### 7.3 技术要点

必须监听微信广告组件三个事件：

- `onLoad`：加载成功
- `onError`：加载失败 → **降级为"分享求助"**
- `onClose`：**必须检查 `isEnded`**，用户跳过广告不发放奖励

### 7.4 变现预期（修正版）

**参数口径（保守）**：eCPM = 25 元；人均日观看 = 2.5 次；组件使用率 = 60-70%

| DAU | 日广告收入（保守） | v2.0 原估 |
|:---|:---|:---|
| 1,000 | 约 60-80 元 | 150-300 元 |
| 5,000 | 约 300-400 元 | 750-1,500 元 |
| 10,000 | 约 600-800 元 | 1,500-3,000 元 |

> **结论：本项目真正的生死线不是"能不能做出来"，而是"能不能获得 DAU"。** 个人开发者最大的短板是获量，这一条必须在上线前想清楚。

### 9.1 资质要求（个人主体）

| 资质 | 说明 | 周期 | 排期建议 |
|:---|:---|:---|:---|

| 适龄提示 | 微信平台要求 | 即时 | 上线前 |

### 9.2 推广策略

**素材方向**：

- **核心玩法实录**："故意失败-偶尔成功-再次失败"叙事，营造"看似简单实则需要技巧"
- **治愈画风展示**：萌宠角色 + 温暖小镇
- **挑衅式文案**："90% 的人卡在第 8 关"

**投放节奏**：

- 首周：日均 50-100 条，测素材
- 第二周起：筛优质素材，日均 100 条左右
- 重点时段：午休 12:00-13:00、晚间 20:00-22:00

**社交裂变启动**：

- 首周：朋友圈/微信群分享给种子用户
- 第二周：启动"小镇挑战赛"
- 持续：排行榜"差一点"提示驱动自然分享
