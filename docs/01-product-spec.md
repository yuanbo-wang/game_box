# 《云朵小镇·推推奇遇》产品文档 v4.0

> 文档版本：v4.0（个人开发者可行性修正版）
> 编写日期：2026 年 10 月
> 相对 v3.0 的核心变更：玩法二值化（限步通关 + 步数锁死）、第三层社交升级为"小镇每日赛"（全服同题，替代 1v1 挑战链接为主链路）、美术降级为贴纸级、排期改为 3×2 周 MVP 验证节奏

## 一、产品概述

### 1.1 一句话定位

**《云朵小镇·推推奇遇》是一款"治愈系萌宠小镇 + 限步推箱子解谜 + 每日同题竞技"的微信小游戏，核心卖点是"3 秒上手的可爱推箱子，在有限步数内的巧解，以及和全服镇民比谁用的步数更少"。**

### 1.2 设计信条（v4.0 重写）

**v3.0 的筛选器（上手门槛 / 技巧天花板 / 单局时长 / 社交钩子 / 变现卡点）回答的是"这游戏好不好玩"，但没有回答"个人开发者能不能做完、能不能获量"。v4.0 换成个人开发者版筛选器——前两条是死活线，过不了就没有后面。**

| # | 维度 | 判断问句 | 本产品的应对 |
|:---|:---|:---|:---|
| **1. 内容成本**（死活线） | 内容能不能程序生成，而不是手工设计？ | 关卡全部程序生成 + 校验器过滤；每日赛每天 1 关、批量预生成 |
| **2. 分享必然性**（死活线） | 不分享，游戏体验是否残缺？ | 每日赛全服同题 + 结果海报，讨论与炫耀由机制产生 |
| **3. 失败二值化** | 输赢是不是"过 / 不过"？ | **限步通关**：步数耗尽即失败，"差一步"真实存在 |
| **4. 美术依赖度** | 能不能不用美术资源就成立？ | 贴纸级美术：1 张主角图 + 程序化绘制，治愈感靠配色与文案 |
| **5. 广告即需求** | 玩家会不会自己"想看"广告？ | 步数耗尽后加步复活、每日赛额外挑战机会，都是玩家主动点的 |

**取舍规则：第 1、2 条必须过；第 3-5 条至少满足 2 条，否则砍掉。**

### 1.3 历史修正记录（必读）

**v2.0 → v3.0 的修正：**

| 问题 | v2.0 的说法 | v3.0 的修正 |
|:---|:---|:---|
| 品类天然短板 | 未提及 | 明确认定：**推箱子在"单局时长(C)"和"社交钩子(D)"上有结构性缺陷**，靠加机关补不了，必须靠社交层重做 |
| 收入预期 | DAU 1000 → 150-300 元/日 | 按 eCPM 25 元、人均日看 2.5 次激励视频重算：**DAU 1000 → 约 60-80 元/日** |
| eCPM | ">50 元" | 那是微信官方"上限参考值"；**实际区间 15-40 元**，按 25 元做保守测算 |
| 软著排期 | 第 7-8 周提交 | **第 2 周必须提交**（软著是审核前置条件，1-3 个月出证，不能后补） |
| 开发周期 | 8 周 | **12-14 周**（个人开发，含资质等待期） |
| 机关数量 | 首发 5 个 | **首发 3 个**（传送带 / 滑梯弹簧 / 小伙伴），另 2 个延后 |
| PK 设计 | "同一关卡的镜像版本" | **废弃**。改为"同关卡同配置，比最少步数"（镜像版破坏公平性，见 6.5） |
| 收入模型 | 组件使用率 90% | 按更真实的 60-70% 测算 |

**v3.0 → v4.0 的修正（本次）：**

| 问题 | v3.0 的说法 | v4.0 的修正 |
|:---|:---|:---|
| 玩法胜负 | 通关即过关，最少步数是"可选追求" | **限步通关**：每关有步数预算，耗尽即失败（失败二值化，痛感真实） |
| 撤销规则 | "无限撤销，无成本" | 撤销仍无限次，但**步数不返还**：棋盘可回退，预算收不回 |
| 第三层社交 | 异步 PK（1v1 挑战链接接龙） | **升级为小镇每日赛**（全服每天同一关、每人一次机会）；1v1 挑战链接降为 v1.1 扩展 |
| 内容生产 | 30 关手调 + 上线后每 2 周加 10 关 | 关卡程序生成 + 校验器过滤；每日赛关卡批量预生成 |
| 美术 | 主角 4 组骨骼动画 + 多层视差 + AI 背景 | **贴纸级**：1 张静态图 + 弹跳补间，视差降为静态背景 |
| 开发节奏 | 13 周直线排期 | **3×2 周 MVP 验证**：先验证两条死活线，再投入完整版（见第八节） |

> **重要提示**：本文档的 TAM/SAM 数据来自公开渠道，仅用于方向判断，不作为财务承诺。

## 三、核心玩法设计

### 3.1 基础玩法（v4.0：限步通关）

经典推箱子：玩家在网格地图移动，推动"小物件"前进（只能推、不能拉），撞墙或无路可推时停下。**在步数预算内将所有物件推到"星光台"上即通关；步数耗尽仍未完成即失败。**

**限步规则（v4.0 核心变更）**：

- 每关有一个**步数预算**（`maxSteps`），由该关最优解步数 + 容错余量派生（见 3.3）
- 每次有效移动消耗 1 步；步数耗尽且未完成 → 关卡失败（**失败二值化：过 / 不过**）
- **撤销不返还步数**：棋盘可以无限回退，但已消耗的预算收不回来——撤销用于"救棋局"，不用于"省步数"
- 失败后三种出路：看激励视频**加步复活**（+3 步，每关 1 次）、重开本关、求助好友

操作（移动端）：

- **滑动屏幕** → 角色朝对应方向移动一格
- **长按角色** → 高亮当前可推动物件范围
- **双指缩放** → 全局视野 / 局部视野切换（低优先级，可延后）
- **撤销按钮** → 无限次，但**不返还步数**（UI 必须明确提示这一点）

### 3.2 首发机制（3 个，砍掉 2 个）

#### 机制一：彩虹传送带 ✅ 首发

场景中有彩色传送带，物件被推到传送带上则自动运送到相邻区域。

- **教学关卡**：第 1-5 关，单条直线传送带
- **设计要点**：传送带让玩家需要"预判两步之后的局面"，是**性价比最高的机制**
- **风险**：低

#### 机制二：滑梯与弹簧 ✅ 首发

滑梯上的物件被推动后自动滑行至障碍或平地；弹簧格把物件弹射到远处。

- **教学关卡**：第 6-10 关，单向滑梯
- **设计要点**：把"精确落点"变成"范围落点"，降低操作精度要求，提升趣味
- **风险**：低

#### 机制三：小伙伴合作 ✅ 首发

可切换控制主角与小伙伴（小兔子、小松鼠），小伙伴可达狭窄通道，需配合解谜。

- **教学关卡**：第 11-15 关，主角推物件开门，小伙伴穿门到另一侧推物件
- **设计要点**：切换控制 = 一个关卡等于两个棋盘，**深度高但实现中等**
- **风险**：中（需做"双角色状态机"，但和核心引擎同构）

#### 机制四：音乐花丛 ⏸️ 延后至 v1.1

靠音效变化判断隐藏目标位置。

- **砍掉原因**：**在静音环境（地铁/办公室）下直接不可玩**，与"碎片化场景"核心定位冲突
- **补救方案**：若要做，必须提供视觉替代（颜色/光晕变化），不能只靠声音

#### 机制五：镜子小屋 ⏸️ 延后至 v1.1

镜像区域联动移动。

- **砍掉原因**：状态空间翻倍，**关卡设计成本与难度控制成本极高**；且玩家理解成本高，与"零门槛"冲突
- **补救方案**：可做成独立的"镜屋模式"，不混入主线

### 3.3 关卡结构（首发 30 关）

| 章节 | 主题 | 关卡 | 核心机制 |
|:---|:---|:---|:---|
| 第一章·搬新家 | 小镇入口 | 1-10 | 基础推箱子 + 彩虹传送带 |
| 第二章·滑梯乐园 | 游乐区 | 11-20 | 传送带 + 滑梯弹簧 |
| 第三章·朋友派对 | 小镇广场 | 21-30 | 传送带 + 滑梯 + 小伙伴全面融合 |

**步数预算派生（v4.0 核心规则）**：

```
maxSteps = optimalSteps + 容错余量

教学关    余量 +8~10   → 几乎必过，绝不劝退
普通关    余量 +4~6    → 允许试错，"想稳过但不轻松"
魔鬼关卡  余量 +1~2    → 真正的"就差一步"
```

- 每关的 `optimalSteps` 由求解器算出，`maxSteps` 自动派生——**关卡生产不依赖人工估算难度**
- 难度曲线不再用"步数绝对值"表达，而用**容错余量**：余量越小，容错越低，紧张感越强

**难度曲线（每章内部）**：

- 第 1-3 关：教学关（引入新机制，余量最大）
- 第 4-7 关：组合应用（余量中等，需要几步思考）
- 第 8 关：**魔鬼关卡**（余量最小，专门制造"就差一步"，见 6.3）
- 第 9-10 关：综合挑战

**关于 30 关**：MVP 验证阶段（见第八节）只做 **10 关**；数据过关后再扩到 30 关（程序生成 + 校验器过滤，不再依赖手工设计）。

### 3.4 反馈系统

| 反馈类型 | 触发条件 | 表现 |
|:---|:---|:---|
| 操作反馈 | 每次移动 | 脚下星星粒子 + "啾"音效 |
| 推动反馈 | 物件被推动 | 物件弹跳动画 + 地面脚印 |
| 传送带激活 | 物件上传送带 | 彩虹光效 + 欢快音效 |
| 正确放置 | 物件到目标点 | 物件发光 + 风铃声 + 星光台亮起 |
| 全部完成 | 所有物件归位 | 全屏星星粒子 + 通关音乐 |
| 撤销 | 点击撤销 | 棋盘回退动画 + **"步数不返还"轻提示**（v4.0：必须让玩家感知到规则） |
| 卡关 | 物件被推到死角 | 物件抖动 + 角色歪头 + 提示可撤销 |
| **步数告急** | 剩余 ≤2 步 | 步数 UI 变红 + 心跳音效（v4.0 紧张感来源） |
| **步数耗尽** | 预算用尽未完成 | 柔和失败动画 + "再加 3 步试试？"（不羞辱，直接给复活入口） |

### 3.5 辅助功能

- **步数 UI**：剩余步数常驻且最醒目（`stepBudget - steps`）
- **撤销 / 重置**：次数无限，但**撤销不返还步数**（v4.0 规则，UI 明示）
- **提示系统**：每关 3 次免费提示，超出观看激励视频
- **复活**：步数耗尽后，激励视频 +3 步（每关 1 次），复活后继续当前棋盘
- **角色换装**：通关得星星解锁装扮（纯装饰，v1.1）
- **半开放探索**：部分关卡信息藏在场景装饰中

### 3.6 小镇每日赛（v4.0 新增）

主线之外的第二条玩法主线：**全服每天同一关、每人一次机会、比步数**。

- 主线 = 内容与教学（自给自足，不制造压力）
- 每日赛 = 竞技与传播（一天一关、一次机会、结果海报）
- 两者共用同一套限步引擎与关卡预生成管线（规则与商业细节见 6.5，技术实现见开发文档第八章）

## 四、美术风格设计

### 4.1 视觉定位

**柔和手绘 + Q 版卡通 + 温暖治愈**

| 规范 | 内容 |
|:---|:---|
| **色彩** | 奶油白、淡粉、薄荷绿、鹅黄为主；辅以天蓝、珊瑚橙；低对比度 |
| **线条** | 圆润粗线条，边缘有轻微手绘抖动感（蜡笔/水彩笔触） |
| **背景** | 多层视差：远景云朵彩虹 / 中景小镇建筑 / 近景关卡场景 |
| **光影** | 柔和全局光，物件有淡投影 |

### 4.2 角色与物件

| 元素 | 描述 |
|:---|:---|
| 主角·小狐狸 | 圆滚滚橙色小狐狸，大尾巴，豆豆眼，行走有弹跳感 |
| 主角·小猫（可选） | 奶油色小猫，粉色肉垫，蝴蝶结 |
| 小物件 | 小南瓜、毛线球、礼物盒、小蛋糕（按章节变化） |
| 星光台 | 圆形木质台面，边缘星星装饰，放置后亮起柔光 |
| 彩虹传送带 | 彩色条纹，转动时流光 |
| 滑梯与弹簧 | 木质滑梯；弹簧格为蘑菇造型 |
| 小伙伴 | 小兔子、小松鼠，圆润可爱，专属动作 |
| 场景装饰 | 云朵、彩虹、小花、蘑菇、木牌、路灯 |

### 4.3 美术生产流程（v4.0：贴纸级方案）

**v4.0 决策：主角从"4 组骨骼动画"降级为"贴纸级"——1 张静态图 + 弹跳/缩放补间。** 治愈感不靠动画量，靠下面四项按优先级分配：

| 优先级 | 手段 | 说明 |
|:---|:---|:---|
| 1 | **配色** | 奶油白 / 淡粉 / 薄荷绿 / 鹅黄，低对比度——氛围的主要来源 |
| 2 | **文案** | 情绪化文案（见 6.3 / 6.4），成本为零、效果最好 |
| 3 | **粒子** | 星星、脚印、光效（Phaser Graphics 程序化绘制） |
| 4 | **音效** | 单一音效 + 变调复用，文件数最少化 |

**生产分工**：

- **AI 生成**（仅背景与宣传）：3 章主题背景、场景装饰、封面图——先柔化处理（降对比度 + 统一色调）再使用
- **程序化绘制**（核心元素）：格子、墙、目标点、传送带、滑梯、弹簧、网格线、UI 边框、粒子——全部 Phaser Graphics，零图片依赖
- **贴纸素材**（少量）：主角 1 张、小伙伴 2 张、物件 4 张——AI 生成 + 人工修边，或先用色块占位

**明确砍掉（v4.0）**：

- 主角 4 组动画（待机/移动/推送/歪头）→ 1 张图 + 补间
- 小猫皮肤（降为 v1.1）
- 多层视差（远景/中景/近景）→ 单张静态背景

> **⚠️ 前置验证项**：AI 生成风格的**一致性**仍是隐性工作量，但不再阻塞开发——**第 1 段 MVP 全程使用占位图形**；AI 样张验证从第 2 段数据过关后才启动，通过后批量生产，不通过则全部程序化绘制。

## 五、技术方案（摘要）

> 详细内容见 `docs/03-dev-spec.md`

| 维度 | 选择 | 理由 |
|:---|:---|:---|
| 引擎 | Phaser 3 | 2D 解谜首选，社区成熟，支持微信小游戏适配层 |
| 语言 | TypeScript | 类型安全，适合复杂解谜逻辑 |
| 状态管理 | 纯函数棋盘引擎 | 逻辑与渲染解耦，便于单测与撤销/回放 |
| 部署 | 微信小游戏 | 目标平台 |
| 后端 | 微信云开发（云函数 + 云数据库） | 仅用于每日赛关卡分发、成绩分布与防作弊（v4.0） |

**核心架构**：棋盘引擎为纯函数模块，每次操作返回**新的不可变状态** + **事件列表**，渲染层根据事件播放动画。

**包体预算**：代码包 ≤ 2MB + 资源包 ≤ 2MB（总计 ≤ 4MB，首包建议压到 3.5MB 以内留余量）。

## 六、社交化改造方案（v4.0 核心）

### 6.1 问题定义：推箱子的"社交原罪"

| 维度 | 推箱子的天然状态 | 阻碍 |
|:---|:---|:---|
| 社交钩子 | 成就感是"内敛"的（我解出来了） | 不如消除类有直观可比性 |
| 单局时长 | 后期关卡 5-10 分钟正常 | 破坏了异步竞技的"同一起跑线"前提 |

**核心命题**：把"内敛的成就感"改造成"外显的、可比的身份标签 / 痛点"。

**隐藏的致命问题**：推箱子的成绩**没有天然可比性**。消除类比"过了没有"（二值、直观、人人焦虑）；推箱子是"47 步 vs 43 步"，两者都过了，**玩家感受不到差距的痛感**。

**v4.0 的解法**：① 限步通关把结果二值化（过 / 不过），痛感真实 ② 每日赛把比较对象从"某个人"换成"全服"，"击败 X%"让单人也能感知自己的水平坐标。

### 6.2 三层社交结构（v4.0 修订）

```
┌─────────────────────────────────────────────┐
│  第三层：小镇每日赛（全服同题对抗）           │  ← 获客层
│  每天一关全服同题，每人一次机会，比步数       │
├─────────────────────────────────────────────┤
│  第二层：求助机制（弱关系互动）               │  ← 留存层
│  卡关 → 求好友 → 好友点一下"加油"           │
├─────────────────────────────────────────────┤
│  第一层：魔鬼关卡（限步强化"制造痛点"）       │  ← 情绪层（地基）
│  每章第 8 关，容错余量 +1~2 的"看似能过"     │
└─────────────────────────────────────────────┘
```

**因果关系**：魔鬼关卡制造"痛" → 求助把"痛"转成"关系互动" → 每日赛把"互动"转成"传播链"。

**没有第一层，上面两层都是空的。** 参考《羊了个羊》：它的裂变不是设计出来的，是第二关的难度逼出来的。

**为什么第三层从"1v1 挑战链接"改为"每日赛"（v4.0）**：

| 维度 | 1v1 挑战链接 | 小镇每日赛 |
|:---|:---|:---|
| 内容成本 | 每次挑战一套链路流程 | 每天 1 关，可批量预生成 |
| 分享必然性 | 需要玩家主动发起挑战 | 全服同题 + 海报，讨论与炫耀由机制产生 |
| 公平性 | 依赖链路传递，存在刷分风险 | 每人一次机会，服务端强校验 |
| 社交密度 | 点对点（一次一人） | 点对面（全服讨论"今天的关"） |

1v1 挑战链接接龙**不删除，降为 v1.1 扩展**（见 6.5 末）。

### 6.3 第一层：魔鬼关卡

**设计原则**：《羊了个羊》的第二关不是"随机难"，是精心设计的"**看似能过**"。

| 要素 | 做法 | 为什么 |
|:---|:---|:---|
| 视觉上可解 | 棋盘是标准规格，不吓人 | 玩家愿意开始 |
| 有明确接近感 | 前 70% 顺利，最后 1-2 个物件卡死 | 制造"就差一点"的痛感 |
| 有微小侥幸 | 有 1-2 种操作顺序能过，但试不出来 | 让玩家相信"再试一次就行" |
| 失败不羞辱 | 提示"再想想，你一定可以" | 不破坏治愈系人设 |

**关卡结构**（6×6，2 物件示例）：

```
初始状态：
  - 物件 A 与目标点几乎在一条直线，看起来推 3 步就到
  - 物件 B 需绕路，路径上有个"看起来能过"的窄缝

真实解法：
  - 必须先推 B 到特定位置堵住退路，再用 A 完成"空间交换"

痛点设计（v4.0 限步强化）：
  - 90% 的人先推 A（最直觉）→ B 永远推不出来（死局）
  - 游戏不说"你错了"，只显示"再试试"；撤销可回退棋盘，但步数不返还
  - 容错余量 +1~2：步数耗尽即失败——"就差一步"是真实的失败，不是文案
```

**关键**：让玩家在**第 3-5 次尝试后**才意识到"我一开始的思路就是错的"。这个"意识到"的瞬间，就是分享欲望最强的时刻。

**v4.0 补充**：限步让"魔鬼"从文案变成了机制——v3.0 里"差一点"只是结算页的对比数字（玩家其实已经过关了）；限步后步数耗尽即失败，"痛感"才真实存在。**限步与魔鬼关卡必须同时上线**，缺一个都不成立。

**配套造势**：

- 关卡名：《就差一步》
- 通关文案："你用了 X 步，比 92% 的镇民都聪明 🎉"
- 分享海报印："**据说 90% 的人在这里放弃**"

### 6.4 第二层：求助机制

推箱子的求助**不能照抄**《羊了个羊》的"分享给好友帮你玩"——推箱子没法"帮玩"（给好友他也得自己解）。三种形态：

| 形态 | 机制 | 好友收到 | 侵入性 |
|:---|:---|:---|:---|
| **① 加油** | 卡关时点"呼叫小伙伴" | 可爱卡片，点一下给"加油"，玩家得 1 次提示 | 最轻（高频、无压力） |
| **② 传地址** | 把这一关送给好友挑战 | 好友进入**同一关**，双方独立解 | 中 |
| **③ 组队解谜** | 邀请好友一起解 | 好友能看到玩家已走的前 N 步，从中间继续 | 重（实现复杂） |

**首发只做 ① 和 ②。** ③ 需序列化状态传输，ROI 不高，延后。

**反骚扰硬约束**：

1. 每人每日求助上限 **3 次**（对齐微信分享频次隐性限制）
2. 同一好友 **24 小时内只能被求助 1 次**
3. **求助必须"给好友东西"**：好友点一下能拿到星星/提示，这样他才不烦
4. **不做"分享才能复活"**（微信不鼓励，伤体验）

**文案设计**（情绪化，别机械）：

| 场景 | 文案 |
|:---|:---|
| 玩家发出求助 | "我在《就差一步》卡住了，小松鼠说它也没办法 🥺" |
| 好友看到 | "你的朋友在《就差一步》需要帮助！点一下为他加油 ✨" |
| 好友帮完后 | "你帮 TA 加油了！获得 1 颗小星星 ⭐" |

### 6.5 第三层：小镇每日赛（v4.0 核心）

**⚠️ 废弃 v3.0 的"1v1 挑战链接为主链路"设计。** 理由：

- **内容与流程成本**：每条挑战链接都是一次点对点流程，无法沉淀为"集体话题"
- **分享不是必然的**：需要玩家主动发起，且对手只有一个——分享动机弱
- **公平性脆弱**：链接转发多手后，防作弊与成绩校验复杂

**正确做法：全服每天同一关、每人一次机会、比步数。**

```
流程：
1. 每天 00:00 全服发布同一关（预生成管线产出，最优步数落在 6-15）
2. 每位玩家每天 1 次免费挑战机会
   - 步数耗尽 → 看激励视频 +3 步（每日 1 次），继续同一个棋盘
   - 机会内未完成 → 今日无成绩，明早再来
3. 通关 → 提交成绩 → "用了 5 步 · 击败 87% 的镇民"
4. 生成结果海报 → 截图 / 转发分享
5. 次日 00:00 换新关 → 形成"今天你过了吗"的日常讨论
```

| 设计点 | 作用 |
|:---|:---|
| 全服同题 | 成绩天然可比，"今天的关"成为公共话题 |
| 每人一次机会 | 稀缺感 + 公平性（大家都只有一次）；服务端强校验 |
| 加步复活仅 1 次 | 广告点天然且克制，不破坏竞技感 |
| 只显示击败百分比 | 弱者不被碾压、强者有炫耀感（不显示具体排名） |
| 每天换新关 | 固定回访理由 + 内容成本 = 每天 1 关 |

**记分口径（关键细节）**：只算**当次挑战消耗的步数**（越少越好），步数并列比用时。

- 一次机会制下不存在"反复重试刷最优"的问题——所有人在"一次过"的约束下比解谜质量
- 与主线的区别：主线允许多次重试（内容体验优先），每日赛不给重试（竞技公平优先）

**排行榜（降级为辅助）**：

- 每日赛成绩页自带"击败 X%"（无需好友数据即可感知水平）
- 好友榜（开放数据域）：降为 v1.1，每日赛分布统计已承担对比功能
- **不做总榜**

**v1.1 扩展：1v1 挑战链接**（保留 v3.0 设计，验证期后追加）：

- 通关第 N 关 → 发起挑战 → 好友进入同配置复刻关 → 揭晓成绩对比 → 接龙
- 核心约束不变：隐藏对方成绩、差值 ≤2 触发再挑战、输方可反向挑战

### 6.6 分享激励设计

| 场景 | 激励 |
|:---|:---|
| **每日赛生成结果海报** | 结果页主按钮，分享即自然发生（不加额外奖励，靠炫耀/哭惨情绪驱动） |
| 通关后分享成绩 | 1 次免费提示 |
| 邀请好友首次进入 | 双方各得 1 次"机关预览" |
| 卡关超 5 分钟 | 提示"求助好友" |

**注意**：分享**不可硬来**，单用户每日主动分享 ≤ 3 次；每日赛的分享动机来自结果本身，不给分享加奖励。

### 6.7 落地优先级

| 优先级 | 功能 | 为什么先做 | 工作量 |
|:---|:---|:---|:---|
| **P0** | 限步通关 + 步数锁死（引擎） | 玩法地基，全项目围绕它 | 3-4 天 |
| **P0** | 魔鬼关卡（容错余量 +1~2） | 社交地基，没它后面都空 | 2-3 天 |
| **P0** | 小镇每日赛（一次机会 + 加步复活） | 核心获客引擎，含后端 | 4-6 天 |
| **P0** | 结果海报生成 | 传播载体，每日赛的出口 | 2 天 |
| **P1** | 求助-加油（形态①） | 承接情绪的留存层 | 1-2 天 |
| **P2** | 1v1 挑战链接 / 好友榜 | v1.1 扩展 | — |

**顺序不能反**：先限步（制造真实二值失败）→ 再魔鬼关卡（制造痛点）→ 最后每日赛（放大传播）。

### 6.8 三个必须警惕的坑

1. **限步做成"随机劝退"**：容错余量必须由求解器派生，不能拍脑袋；教学关余量必须足够大。若教学关完成率 <90%，第一个要放宽的就是余量规则。
2. **每日赛难度波动**：每天一关意味着"没有机会重来"——某天关卡太难，当天所有轻度用户都会流失。**预生成管线必须校验最优步数区间（6-15）并人工抽检**，宁可比主线略简单。
3. **忘记微信分享限制**：单用户每日主动分享 ≤3 次；不能"必须分享才能继续"；分享卡片必须走官方接口。

## 七、商业化设计

### 7.1 变现模式：纯 IAA（激励视频）

**硬约束**：个人开发者在微信小游戏平台**无法开通内购支付**，只能广告变现。若后期想开内购，需升级企业主体（需公司资质、对公账户）。

### 7.2 广告触发点（v4.0 更新）

| 触发场景 | 类型 | 频次限制 | 说明 |
|:---|:---|:---|:---|
| **步数耗尽加步复活（+3 步）** | 激励视频 | 每关 1 次 | v4.0 最核心的广告点：玩家主动想看 |
| **每日赛加步复活** | 激励视频 | 每日 1 次 | 一次机会制下的唯一"续命"入口 |
| 获取提示 | 激励视频 | 每关最多 2 次（前 3 次免费） | — |
| 解锁隐藏关卡 | 激励视频 | 每章 1 次 | — |
| 领取每日奖励 | 激励视频 | 每日 1 次 | — |
| 结算界面"翻倍" | 激励视频 | 每日 3 次 | — |

**不设 Banner 和插屏广告**（破坏解谜沉浸感）。

**为什么限步让广告模型变好（v4.0）**：

- 旧口径（通关即过）：失败率低 → 复活广告没人看
- 新口径（限步二值）：失败成为常态 → "差 1 步"时加步复活是**玩家自己想要的**，而不是被塞的广告

### 7.3 技术要点

必须监听微信广告组件三个事件：

- `onLoad`：加载成功
- `onError`：加载失败 → **降级为"分享求助"**
- `onClose`：**必须检查 `isEnded`**，用户跳过广告不发放奖励

### 7.4 变现预期（v4.0 维持保守口径）

**参数口径（保守）**：eCPM = 25 元；人均日观看 = 2.5 次；组件使用率 = 60-70%

| DAU | 日广告收入（保守） | v2.0 原估 |
|:---|:---|:---|
| 1,000 | 约 60-80 元 | 150-300 元 |
| 5,000 | 约 300-400 元 | 750-1,500 元 |
| 10,000 | 约 600-800 元 | 1,500-3,000 元 |

> **结论：本项目真正的生死线不是"能不能做出来"，而是"能不能获得 DAU"。** 个人开发者最大的短板是获量，这一条必须在上线前想清楚。

**v4.0 补充**：每日赛承担两个额外作用——① 固定回访理由（提高 DAU 稳定性）② 海报传播（降低获量成本）。但**获量仍是最大不确定性**，故验证节奏改为 3×2 周（见第八节），上线前必须想清楚获量方案。

## 九、上线与推广

### 9.1 资质要求（个人主体）

| 资质 | 说明 | 周期 | 排期建议 |
|:---|:---|:---|:---|
| **软件著作权** | 源代码前 30 页 + 后 30 页（每页 ≥50 行） | **1-3 个月** | **第 2 周提交（关键）** |
| **ICP 备案** | 工信部备案 | 2-4 周 | **先确认是否必需** |
| 小游戏隐私协议 | 微信平台要求 | 即时 | 上线前 |
| 适龄提示 | 微信平台要求 | 即时 | 上线前 |

> **⚠️ 软著是审核前置条件，不能后补。** v2.0 把它排在第 7-8 周是致命错误。
> **⚠️ ICP 备案**：v4.0 引入每日赛云函数（微信云开发），场景与 v3.0 的单机假设不同，**必须在微信开放平台后台确认是否需要**，以明确答复为准，不要照抄。

### 9.2 推广策略

**素材方向**：

- **核心玩法实录**："故意失败-偶尔成功-再次失败"叙事，营造"看似简单实则需要技巧"
- **治愈画风展示**：萌宠角色 + 温暖小镇
- **挑衅式文案**："90% 的人卡在第 8 关"

**投放节奏**：

- 首周：日均 50-100 条，测素材
- 第二周起：筛优质素材，日均 100 条左右
- 重点时段：午休 12:00-13:00、晚间 20:00-22:00

**社交裂变启动**：

- 首周：朋友圈/微信群分享给种子用户

## 十一、附录

### 11.1 核心术语表

| 术语 | 含义 |
|:---|:---|
| 小物件 | 可推动的箱子（南瓜、毛线球、礼物盒等） |
| 星光台 | 物件的目标放置点 |
| 机关 | 可交互机制（传送带/滑梯弹簧/小伙伴） |
| **限步通关** | v4.0 核心规则：每关有步数预算，耗尽未完成即失败 |
| **步数预算（maxSteps）** | 关卡允许的最大步数 = 最优步数 + 容错余量 |
| **步数锁死** | v4.0：撤销回退棋盘，但不返还已消耗的步数 |
| **容错余量** | maxSteps − optimalSteps；教学 +8~10 / 普通 +4~6 / 魔鬼 +1~2 |
| 魔鬼关卡 | 每章第 8 关，容错余量最小的刻意卡点 |
| **小镇每日赛** | v4.0 第三层社交：全服每天同一关、每人一次机会、比步数 |
| **加步复活** | 步数耗尽后看激励视频 +3 步（每关 / 每日 1 次） |
| 最优步数 | 关卡最少通关步数，由求解器算出（派生 maxSteps 的基数） |
| 加油 | 最轻量求助形态（好友点一下给提示） |
