## 第一部分 需求梳理（精简版）

### 1.1 一句话需求

将「治愈系萌宠小镇 + 限步推箱子解谜 + 每日同题竞技」做成**微信小游戏**（个人主体、纯 IAA 广告变现），以 **3×2 周 MVP 验证**先行证明两条死活线（内容成本、分享必然性），数据过关后再投入完整版。

### 1.2 需求六要素

| 要素 | 内容 |
|:---|:---|
| 背景 | 个人开发者立项。推箱子品类在"单局时长 / 社交钩子"上有结构性缺陷，v4.0 用「限步二值化 + 每日赛」重做社交层 |
| 用户 | 核心：18-35 岁治愈系轻度玩家（碎片时间）；传播：爱晒成绩的对比型用户 |
| 目标 | 验证"分享必然性"是否成立；建立分享率/留存基线；以低成本争取自然量变现 |
| 范围（做） | 限步引擎、10 关（MVP）、每日赛 + 结果海报、加步复活广告、求助-加油；完整版 30 关 + 3 机关 |
| 范围（不做） | 内购（个人主体不可行）、Banner/插屏广告、总榜、音乐花丛/镜子小屋（v1.1）、买量（经济模型不支持，见 2.3） |
| 约束 | 个人主体资质；纯 IAA；软著/备案为前置；首包 ≤3.5MB；3×2 周验证节奏 |

### 1.3 目标与成功指标（口径与 Go/No-Go 判据对齐）

| 层级 | 指标 | 口径 | 判据 |
|:---|:---|:---|:---|
| 第 1 段（W1-2） | **自发分享** | 20 人测试中主动截图发群的次数 | **> 0（核心）** |
| 第 1 段 | 重试意愿 | 单关平均重试次数 | ≥ 2 |
| 第 1 段 | 完成率 | 教学关 / 魔鬼关完成率 | 教学 ≥90%；魔鬼 30-70% |
| 第 2 段（W3-4） | 分享率 | 分享次数 ÷ DAU | 记录基线（无绝对判据，作第 3 段决策依据） |
| 第 2 段 | 每日赛参与率 | 玩过每日赛的 DAU ÷ 总 DAU | 记录基线 |
| 第 2 段 | 7 日留存 | 同批用户 7 天后回访 | 记录基线 |
| 商业（远期） | ARPDAU | 人均观看次数 × eCPM ÷ 1000 | 保守实测约 0.06 元（见 2.3） |

### 1.4 方案对比（"怎么做这个项目"）

| 维度 | 方案 A：3×2 周三段验证 **【推荐】** | 方案 B：13 周直投完整版 | 方案 C：纯单机版（砍每日赛） |
|:---|:---|:---|:---|
| 思路 | 每 2 周验证一条假设，过不了不进入下一段 | 一次做完再上线，成败 3 个月后揭晓 | 不做后端/社交，最小单机解谜 |
| 实现成本 | 低（6 周内见结论） | 高（13 周 + 资质等待） | 最低（约 2-3 周） |
| 开发复杂度 | 中（引擎 + 轻后端） | 高 | 低（纯前端） |
| 用户体验 | 完整链路可体验（含海报传播） | 完整 | 缺传播层，体验残缺 |
| 风险 | **最低：最大不确定性前置暴露** | 最高：三个未验证假设同时下注 | 中：无法验证第 2 条死活线 |
| 上线时间 | 6 周见决策结论；13 周可上线 | 13-14 周 | 4-6 周，但验证不完整 |
| 结论 | **采用** | 否决：赌注太大 | 否决：丢掉"分享必然性"的验证装置 |

**推荐 A 的核心理由**：个人开发者赌的不是钱，是时间。A 把"要不要继续"从第 13 周提前到第 2 周；且第 1-2 段沉淀的引擎 / 关卡管线 / 云开发骨架均可复用（转向成本仅 4 周）。

### 1.5 关键风险（Top 7）

| # | 风险 | 概率 | 影响 | 应对要点 |
|:---|:---|:---|:---|:---|
| R1 | **获量困难（最大风险）**：无买量预算、自然量不可控 | 高 | 高 | 每日赛海报裂变优先于买量；第 3 段用数据决定是否投钱；做好"不买量起不来"的心理预期 |
| R2 | 自发分享 = 0 | 中 | 高 | 第 1 段 20 人测试直接验证；不成立先改海报/对比口径，一轮无果按"转向"处理 |
| R3 | 变现门槛：流量主需累计 UV≥1000 才可开通（开通前收入为 0） | 事实项 | 中 | 接受"先有量、后有钱"；验证期不接广告也不影响验证结论 |
| R4 | 限步劝退：教学关完成率 <90% | 中 | 高 | 容错余量分级（教学 +8~10）；不达标立即放宽余量、魔鬼关后移 |
| R5 | 每日赛难度波动：每天一关、不可重来 | 中 | 中 | 预生成强制校验最优步数 ∈[6,15] + 每周人工抽检；宁易勿难 |
| R6 | 合规周期：备案（约 1-2 周+）与软著（约 30-60 个工作日）为硬前置 | 中 | 中 | 第 0 周交备案、第 2 周交软著；体验版先行，不阻塞 MVP 验证 |
| R7 | 品类留存天花板：MVP 无 meta 成长线，长留存靠每日赛独撑 | 中 | 中 | 第 2 段测 7 日留存基线；不足则补轻量成长线（星星/换装）再决策 |

### 1.6 关键假设（可推翻；未验证项已标注）

1. 商业口径：eCPM 25 元 / 组件使用率 60-70% / 人均日看 2.5 次——**保守假设，非承诺**（行业激励视频 eCPM 参考区间 30-150 元，项目取低于区间下限的口径，属防御性估计）
2. "限步二值化能制造真实痛感"——**未验证**，第 1 段测（判据：重试 ≥2）
3. "海报 + 击败 X% 能驱动自发分享"——**未验证**，第 1-2 段测
4. 关卡程序生成覆盖 60%、约 40% 需人工——工作量假设，影响内容扩张速度
5. 20 人测试代表更大样本——小样本，仅作方向性信号
6. 时间投入按每周 5 个工作日量估算

### 1.7 下一步（编号 · 按优先级）

**P0 · 第 0 周（3 天内全部启动，均不占开发主线）**

1. 注册个人主体小游戏账号，拿到 AppID
2. **立即提交 ICP 备案**（已确认强制，见 2.5；利用审核期并行开发）
3. 本地环境跑通空场景（Vite + Phaser 3 + Vitest + `VITE_PLATFORM` 环境变量）
4. 微信后台确认并存证三个事实：可用类目 / 流量主开通条件 / 免版号边界（截图存档）

**P1 · 第 1 段（W1-2）**

5. 限步引擎（步数锁死 + 结算顺序 + 链条上限）+ ≥25 个单测 + 传送带机制
6. 10 关（程序生成 + 校验器过滤）+ 本地对比卡片（截图即分享素材）
7. **第 2 周提交软著**（自助 0 元；真实代码、三处名称版本一致）
8. 20 人测试，回收 R2/R4 判据数据

**P2 · 第 2-3 段**

9. 每日赛 + 海报 + 体验版 → 四条基线 → 决策矩阵（继续 / 迭代 / 转向 / 止损）

**建议新增（低成本前置信号）**

10. 找 3-5 名目标用户（18-35 岁、女性优先）先玩现有交互稿：不写代码就先拿到"推箱子 + 限步是否劝退"的第一手定性反馈

## 第二部分 可行性评估

### 2.1 结论先行

**有条件可行（Conditional Go）**：

- **技术**：能做出来（路径成熟，工程量可控）
- **产品**：设计方向正确，但两条死活线**尚未验证**（2-6 周内可证伪）
- **商业**：天花板低（月入数千元级），本质是"练手 + 资产 + 彩票"，不是赚钱项目
- **最大不确定性**：不在开发，在**获量**

综合建议：**按 3×2 验证节奏启动**，接受"大概率赚小钱或不赚钱"的预期，把止损线写死在流程里。

### 2.2 六维评分

| 维度 | 评分 | 一句话结论 |
|:---|:---|:---|
| 产品设计 | ★★★★☆ | 限步二值化 + 每日赛直击推箱子"社交原罪"；三层社交因果自洽 |
| 技术实现 | ★★★★☆ | Phaser 3 + 纯函数引擎路径成熟；求解器性能与机关组合是主要工程风险点，可控 |
| 内容生产 | ★★★☆☆ | 程序生成方向正确；但 40% 人工设计量 + 每日赛持续抽检是真实成本 |
| 商业变现 | ★★☆☆☆ | 纯 IAA 天花板低；UV≥1000 才能开通广告；单位经济薄（ARPDAU ≈ 0.06 元） |
| 获量能力 | ★★☆☆☆ | 最大瓶颈：无预算、无发行资源，品类自然量依赖裂变成立 |
| 合规资质 | ★★★★☆ | 路径清楚（备案 + 软著 + 隐私 + 适龄）；周期是唯一变量，已给排期方案 |
| 个人执行 | ★★★★☆ | 3×2 节奏是全案最正确决策：把赌注从 13 周压缩到 4-6 周 |

### 2.3 关键量化：单位经济与获量经济学

**单位经济（用文档自有保守口径测算）：**

```
ARPDAU = 2.5 次/日 × 25 元 ÷ 1000 = 0.0625 元 ≈ 0.06 元/DAU/日
7 日 LTV ≈ 0.44 元     |     30 日 LTV ≈ 1.9 元
```

- 收入梯度（与产品文档 7.4 一致）：DAU 1,000 ≈ 62.5 元/日；5,000 ≈ 312.5 元/日；10,000 ≈ 625 元/日
- **买量判据**：单用户获取成本需低于约 0.4 元才可能 7 日回本；休闲品类获量成本通常为该数值的数倍起步——**买量在此模型下几乎不可能回本**。因此项目只能走"有机裂变"获量路线，这反过来进一步放大 R1/R2 两个风险。
- **价格风险小、量的风险大**：激励视频 eCPM 2026 年行业参考区间 30-150 元，项目口径 25 元已低于区间下限；即使 eCPM 上修，收入问题依然由"量"主导。

### 2.4 最强三张牌 / 最弱三环

**最强的三张牌：**

1. **内容成本趋近于零**：每日赛"每天 1 关 + 批量预生成"，把内容生产从"手工设计"变成"管线作业"
2. **分享内嵌于机制**：结果海报 + "击败 X%" + 魔鬼关卡，分享是玩法出口而非附加动作
3. **止损成本极低**：引擎 / 生成管线 / 云开发骨架可跨题材复用；失败损失是 4-6 周业余时间，不是 13 周

**最弱的三环：**

1. **获量**：个人无预算无发行资源，全链路依赖分享裂变是否成立
2. **商业化**：天花板为月数千元级（DAU 万级时）；且"先有 UV 1000、才有广告收入"的顺序不可绕过
3. **留存结构**：MVP 阶段无养成/成长线，长留存靠每日赛独撑，只有第 2 段数据能回答

### 2.5 政策核查结论（2026-10-10 核查；含对现有文档的 2 处修订建议）

| # | 事项 | 核查结论 | 对项目的影响 |
|:---|:---|:---|:---|
| 1 | ICP 备案 | **强制**（2023-09-01 起，小程序/小游戏需完成备案方可上架）；注册后即可在后台提交，管局审核约 1-2 周 | 《精细执行步骤》A3 的开放问题有了答案：**需要备案**。第 0-1 周提交，利用审核期并行开发 |
| 2 | 免版号边界 | 纯广告变现 + 休闲解谜品类通常可走**免版号**通道；不得含内购；不碰棋牌/敏感题材 | 项目形态（纯 IAA 解谜）在通道内；提审时以平台最新规则为准 |
| 3 | 流量主开通 | 需**累计独立访客（UV）≥1000** 才可申请开通官方广告能力 | "先有量、后有钱"：DAU 1000 不只是收入表的起点，也是变现能力的门槛；低于 1000 时收入为 0 |
| 4 | 个人主体边界 | 不能开通虚拟支付（内购）；不能诱导分享 / 强制关注；命名不得用绝对化词语 | 与文档"反骚扰硬约束"天然一致；维持纯 IAA 路线 |
| 5 | 软著 | **官费已停征（2017-04 起），自助办理 0 元**；代理代办约 500-1,500 元（服务费）；普通通道约 30-60 个工作日；近期审查趋严（原创性比对、材料真实性、纯 AI 生成代码存在不予登记风险） | 见下方两处修订建议 |

**【修订建议 1】**：`docs/01` 与 `docs/04` 中"软著官费 250 元 / MVP 现金成本 250 元"口径已过时，建议改为"自助 0 元（代理 500-1,500 元另计）/ MVP 现金成本 ≈ 0 元"。
**【修订建议 2】**：`docs/04` 任务 A3 从"待确认 ICP 备案需求"更新为"**已确认需备案**，第 0-1 周直接提交"。

> 软著申请注意事项（据近期公开资料）：使用真实工程代码 + 完整注释；申请表、源码页眉、说明书三处的软件名称与版本号必须完全一致；避免纯 AI 生成、无实质智力投入的代码材料。

### 2.6 决策建议（Go 条件与止损线）

**建议：Conditional Go（有条件启动）**，三个条件：

1. **预期管理**：接受"大概率赚小钱或不赚钱，买一个完整的小游戏 0 到 1 发行经验 + 三样可复用资产"——把它当实验，不当赌注
2. **启动条件**：第 0 周把账号注册与备案两条硬前置跑起来（现金成本 ≈ 0 元）
3. **止损纪律**：
   - 第 1 段（W2）：自发分享 = 0 → 先调整一轮（海报 / 对比口径 / 容错余量）；两轮无信号 → 执行"转向"（复用引擎换玩法），不进入第 2 段
   - 第 2 段（W4）：分享率与参与率显著低于基线 → 止损或转向
   - 任何时候不为"沉没成本"追加投入

**明确不做清单**：内购（主体不可行）、买量（经济模型不支持）、总榜、Banner/插屏广告。

### 2.7 综合结论

| 问题 | 结论 |
|:---|:---|
| 技术能不能做出来？ | 能（概率高，取决于时间投入） |
| 产品设计成不成立？ | 方向正确，**2 周内可证伪**（两条死活线） |
| 能不能赚钱？ | 能赚小钱；赚大钱概率低，且瓶颈在获量而不在产品 |
| 值不值得做？ | 值得，但有前提：按验证节奏执行 + 接受低商业预期 + 写死止损线 |

**一句话总结**：这是一个"技术可行、设计有巧思、商业天花板低、成败系于获量"的项目。它的正确打开方式不是"做一个赚钱的小游戏"，而是"用 6 周时间、约 0 元现金，验证一个获客假设 + 沉淀一套可复用资产"——在这个定义下，**期望值为正，建议启动**。
