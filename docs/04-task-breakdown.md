## 零、总览：为什么是 3×2 周

### 0.1 v3.0 排期的问题

v3.0 的 13 周直线排期，把三个**未验证的假设**当成了既定事实：

1. 推箱子解谜（含 v4.0 新增的限步规则）能被玩家接受（未验证）
2. "分享必然发生"（未验证）
3. "关卡内容能生产出来"（未验证）

个人开发者的成本不是钱，是时间。**在验证之前投入 13 周，等于赌三个假设同时成立。**

### 0.2 三段结构

| 段 | 周期 | 目标 | 交付 | Go/No-Go 判据 |
|:---|:---|:---|:---|:---|
| **第 1 段** | W1-2 | 最小可玩闭环 | 限步引擎 + 10 关 + 本地对比 | 20 人测试中**有人自发分享成绩**；平均重试 ≥2 次 |
| **第 2 段** | W3-4 | 每日赛 + 传播验证 | 每日赛 + 结果海报 + 体验版 | 分享率与 7 日留存**记录基线**（第 3 段决策用） |
| **第 3 段** | W5-6 | 按数据决策 | 决策结论 | 加内容 / 换题材 / 止损 |

**两条纪律**：

1. 每段的 Go/No-Go 没过，**不允许惯性进入下一段**
2. 周期为名义 2 周（10 个工作日），任务总量约 12-15 人日，**允许顺延至第 3 周**；时间不够时优先压缩交付规模（例如测试 20 人 → 10 人），**不得压缩"验证"这个目标本身**

### 0.3 什么在并行

- **资质**：微信主体注册 + ICP 备案提交（第 0 周，已确认强制、免费）+ 软著提交（第 2 周）全程并行，不阻塞 MVP 开发——**备案与软著都是正式上线的前置材料**
- **美术**：第 1 段完全不投入（占位图形）；第 2 段数据过关后才开始贴纸级美术；完整版才做全部资源
- **推广**：第 2 段体验版发布后启动种子用户分享；第 3 段才决定是否用钱买量

### 0.4 三段之后

第 3 段结论为"继续"时，进入 [五、完整版排期](#五完整版排期数据过关后)（8-10 周）。

## 二、第 1 段（W1-2）：最小可玩闭环

> **目标**：用最低成本验证"限步 + 撤销不回步"是否真的好玩，以及**有没有人自发分享**。
> **范围纪律**：只做 1 个机制（传送带）、10 关、占位图形。**不做美术、不做后端、不做每日赛。**

### 2.1 引擎开发（含限步与撤销锁死）

| # | 任务 | 交付物 | 工时 |
|:---|:---|:---|:---|
| C1 | 定义全部类型（`src/engine/types.ts`） | 含 `maxSteps` / `stepBudget` / `failed` | 0.5 天 |
| C2 | `createState()` | 初始化（stepBudget = maxSteps） | 0.5 天 |
| C3 | `move()` 基础版（无机关） | 移动 / 推动 / 撞墙拒绝 / **限步判定** | 1 天 |
| C4 | `checkWin()` + 失败判定 | 胜利优先，其次步数耗尽 | 0.5 天 |
| C5 | `serializeBoard()` / `deserializeBoard()` | **棋盘快照（不含步数）** | 0.5 天 |
| C6 | `undo()` | **回退棋盘，不返还步数** | 0.5 天 |
| C7 | `revive()` + `getRemainingSteps()` | 看广告加步（stepBudget += 3） | 0.5 天 |
| C8 | `computeOptimalSteps()`（BFS 求解器） | 关卡求解 + maxSteps 派生 | 1 天 |
| C9 | 传送带机制（`resolveConveyors()`） | 含连锁递归上限 5 | 1 天 |
| C10 | **单元测试（`tests/engine/`）** | 测试用例 ≥ 25 个（清单见 2.2） | 1.5 天 |

**⚠️ 到这里，代码量应已有 2500-3500 行（含注释）。这就是软著需要的量。**

### 2.2 单测必测清单（v4.0 更新）

```typescript
// tests/engine/move.test.ts + limit-steps.test.ts 必测清单
✓ 撞墙拒绝移动，状态不变（不可变性）
✓ 撞到无法推动的物件，拒绝
✓ 推动物件产生 box_pushed 事件

✓ 边界外移动被拒绝
```

### 2.5 20 人测试（Go/No-Go 第一步）

| # | 任务 | 说明 |
|:---|:---|:---|
| F1 | 找 20 个真人测试 | 微信群/朋友圈，非开发者优先 |
| F2 | 观察三个指标 | 见下表 |
| F3 | 1v1 访谈（至少 5 人） | 开放式问题，见下 |

**三个观察指标**：

| 指标 | 判据 | 说明 |
|:---|:---|:---|
| **自发分享** | 有没有人主动把成绩截图发到群里 | **最重要**。没有 → 分享必然性不成立 |
| **重试意愿** | 平均单关重试次数 ≥ 2 | "差一步"的痛感是否成立 |
| **完成率** | 教学关 ≥ 90%；魔鬼关 30-70% | 门槛与难度是否合理 |

**访谈必问**：

1. 第一次玩，知不知道要干什么？
2. "步数耗尽"的时候，你心里想的是什么？（感受到痛 → 好；觉得烦 → 改）
3. 有没有想给别人看成绩的时刻？为什么？
4. 魔鬼关卡你觉得"再试一次就行"还是"这关是不是无解"？
5. 如果卡住了，你愿意看广告加步还是直接重开？（变现偏好）

### 3.5 体验版发布与数据基线

| # | 任务 | 说明 |
|:---|:---|:---|
| L1 | 发布体验版 | 微信后台"体验版"，无需软著 |
| L2 | 种子用户扩散 | 朋友圈/微信群，100-300 人量级 |
| L3 | 埋点数据观察（2 周） | 见下表 |

**必须记录的四条基线**（数值高低都不是成败，**趋势与对比**才是）：

| 指标 | 说明 | 用途 |
|:---|:---|:---|
| 每日赛参与率 | 玩过每日赛的 DAU / 总 DAU | 每日赛是否成为习惯 |
| 分享率 | 分享次数 / DAU | **分享必然性是否成立** |

- [ ] **Go/No-Go：分享率与参与率是否支持继续投入完整版？**

## 四、第 3 段（W5-6）：按数据决策

> **目标**：不是"继续开发"，而是"决定要不要继续"。

### 4.1 决策矩阵

| 情况 | 数据特征 | 决策 | 行动 |
|:---|:---|:---|:---|
| **继续** | 分享率与参与率健康，留存可接受 | 进入完整版（第五节） | 扩 30 关 + 补机制 + 变现 + 提审 |
| **迭代** | 有参与但分享弱 | 改分享链路，再测 2 周 | 不扩内容，先修分享（海报形式/对比钩子） |
| **转向** | 参与率低，但引擎与管线跑通 | **换题材/换机制，复用引擎** | 用同一套引擎做新玩法原型（2 周） |
| **止损** | 两条死活线都不成立 | 停止项目 | 沉淀引擎与流程，转下一个方向 |

> **注**：第 2 段"复活广告完播率"为**条件性基线**（流量主开通后方可采集），不构成本矩阵的硬判据。

### 4.2 为什么"转向"成本很低

第 1-2 段已经沉淀了三样可复用资产：

1. **纯函数引擎 + 单测**（换玩法时改动集中在 `move()`）
2. **关卡生成/校验管线**（任何网格类玩法通用）
3. **云开发骨架**（每日分发/成绩/海报对很多玩法通用）

这就是"先验证再投入"的复利：**转向损失的是 4 周，不是 13 周。**

## 五、完整版排期（数据过关后）

> 仅当第 3 段结论为"继续"时执行。以下为 8-10 周排期。

### 5.1 开发排期

| 阶段 | 周次 | 内容 | 出口标准 |
|:---|:---|:---|:---|
| **机制补齐** | W7-8 | 滑梯弹簧 + 小伙伴（含组合单测） | 3 机制可用，组合测试通过 |
| **内容扩展** | W8-10 | 剩余 20 关（生成 + 抽检）+ 难度调优 | 30 关全量过校验 |
| **美术贴纸化** | W9-11 | 3 章背景 + 主角/物件贴图 + 音效 | 首包 ≤3.5MB |
| **社交补齐** | W10-11 | 求助机制（加油）+ 埋点上报 | 三层社交闭环 |
| **变现与埋点** | W11 | 5 个广告点 + `isEnded` 校验 + 全量埋点 | 广告测试通过 |
| **测试** | W12-13 | 3 轮外部测试 | 难度曲线定稿 |
| **提审上线** | W13-14 | 软著到位 + 备案完成 → 提审 → 软启动 | 审核通过 |

**注**：软著从第 2 周提交，到 W13 提审时通常已出证（约 30-60 个工作日）；未出证则先上体验版继续收集数据（见风险预案）。备案自第 0 周启动，正常于第 1 段期间完成。

### 5.2 完整版要点（继承 v1 的执行细节）

- 滑梯/弹簧：逐格检测 + 连锁递归上限 5（见开发文档 5.2）
- 小伙伴：状态机复用 `move()`，切换不消耗步数（见开发文档 5.3）
- 求助机制：每日 3 次 + 同好友 24h 冷却（见流程图第 6 张）
- 广告接入：`onLoad` / `onError` / `onClose(isEnded)` 三事件必须处理
- 埋点清单见下表

| 事件 | 参数 |

## 六、里程碑与风险预案

### 6.1 里程碑

| 里程碑 | 时间 | 出口标准 | 阻塞风险 |
|:---|:---|:---|:---|
| **M0 环境就绪** | W0 | AppID + 脚手架跑通 | 无 |
| **M1 玩玩看**（关键） | W2 | 10 关 + 20 人测试 + 软著已提交 | 自发分享为 0 |
| **M2 数据基线** | W4 | 每日赛体验版 + 四条基线 | 每日赛无人参与 |
| **M3 决策** | W6 | Go/No-Go 结论 | 数据不足以判断 |
| **M4 功能完整** | W11 | 30 关 + 3 机制 + 变现 | 时间不足 |
| **M5 上线** | W13 | 审核通过 | **软著未出证** |

### 6.2 风险预案

| 风险 | 触发信号 | 预案 |
|:---|:---|:---|
| **自发分享为 0**（最致命） | W2 测试无人分享 | ① 海报生成提前到第 1 段 ② 换对比口径（剩余步数 / 击败百分比）③ 两条死活线均不成立 → 进入"转向" |
| **限步劝退** | 教学关完成率 <90% | 加大容错余量；魔鬼关编号后移；检查撤销规则提示是否清晰 |
| **限步不痛** | 平均重试 <2 次 | 收紧魔鬼关余量（+1）；步数告急 UI 强化（变红 + 音效） |
| **每日赛无人参与** | 参与率 <10% | 检查入口显眼度；加"今日已完成 X 人"社会证明；调整关卡难度区间 |
| **软著未按时出证** | W11 仍未出证 | ① 加急（额外费用）② 体验版继续收集数据 ③ 等证书再正式发布 |
| **备案未按时完成** | W10 备案仍无进展 | ① 微信后台查询催办 ② 体验版继续验证 ③ 正式提审顺延，不跳过备案 |
| **AI 美术风格不统一** | 样张验证不通过 | 改用"统一素材库 + 换色 + 程序化绘制"（贴纸级方案本按此设计） |
| **机关组合 bug 过多** | 组合单测失败率高 | **砍掉小伙伴机制**（保留传送带 + 滑梯弹簧），降为 v1.1 |
| **包体超限** | 包体 >4MB | ① 背景降质 ② 音效降比特率 ③ 按章节分包 |
| **每日赛关卡断供** | 预生成不足 7 天 | 客户端降级"昨日关卡重玩"；生成脚本必须幂等可重跑 |
| **微信审核不通过** | 提审被拒 | 按反馈修改；常见原因：资质、类目、隐私协议 |

## 附：每日/每周节奏建议

**每日**：

- 上午：写代码（引擎/功能）
- 下午：做内容（关卡/美术）
- 收工前：`git commit`，跑一遍单测

**每周**：

- 周一：确认本周 WBS 任务
- 周五：检查出口标准，记录卡点
- 周末：看一眼包体大小和进度

**每段结束**（v4.0 新增）：

- 对照 Go/No-Go 判据，写下结论与依据
- 结论为"否"时，按[决策矩阵](#41-决策矩阵)选择行动，**不要惯性进入下一段**

**提交规范建议**：

```
feat(engine): 实现限步判定与步数锁死
feat(engine): 撤销回退棋盘但不返还步数
feat(daily): 实现每日赛一次机会状态机
feat(ui): 新增剩余步数告急提示（变红 + 心跳音效）
fix(engine): 修复最后一步完成时误判为失败的问题
docs: 更新产品文档 v4.0
```
