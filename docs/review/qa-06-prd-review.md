## 三、结论

### 3.1 可测性总判断：**修订后即可测**

- **可直接编写用例（无需修订）**：模块 A 引擎核心链路 **FR-01 / FR-02 / FR-03**（限步·锁死·结算顺序，GWT 清晰且与 docs/03 单测清单一致）、**FR-05 传送带主路径**、**FR-07 / FR-08 / FR-09 / FR-13 / FR-14 / FR-15（G1/G2）/ FR-17 / FR-18**。这些需求的 Given/When/Then 可直接映射为用例（`tests/engine/` ≥25 用例清单已在 docs/04 2.2 给出）。
- **需修订后固定断言**：每日赛链路 **FR-10 / FR-11 / FR-12** 与通用广告 **FR-15** 存在口径与状态缺口（QAR-01/02/03/05/07/09/10），须先补齐 `maxSteps` 派生、校验链事实来源、"提交中"状态、降级口径与 duration 定义，方能编写稳定用例。
- **建议随 PRD 修订一并补充**：QAR-04/06/11 的"可断言清单"与边界值，可直接固化进测试用例集。

### 3.2 最关键 3 条

1. **QAR-01**：每日赛缺 `maxSteps`/容错余量规则——服务端步数上界校验无依据，每日赛失败判定与防作弊用例无法固化。
2. **QAR-02**：`usedRevive` 事实来源矛盾——若信任客户端入参，复活 +3 步预算可被谎报，整条防作弊校验链失效。
3. **QAR-03**：每日赛缺"提交中/待确认"状态——提交超时/响应丢失时"一次机会"是否消耗不可判定，续玩与幂等重试用例无确定预期。
